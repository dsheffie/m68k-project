    The core¶

    The out-of-order core that runs uisa is derived from superdupersparc, an out-of-order SPARC V8 core (itself forked from r9999). It is a 32-bit renamed machine with flags, and it executes only the uisa micro-op ISA: its decoder (decode_uisa.sv), ALU (uisa_alu.sv) and guest-semantic ops (uisa_gop.sv) are built from the tables uisa generates from spec/uisa.yaml, and the FPU is the core's double-precision unit, which uisa's FP extension exposes to millicode.

    The PLA translation of common 68k instructions and the millicode for the rest are documented in the uisa reference.

    The front end is work in progress¶

    The back end is RTL: rename, the ROB, the three queues, the execution units, the LSU, the L1D, the 68040 ATC and table walker, and the L2. Most of the 68k front end is still a C++ model, fe68k.cc, which the simulation calls once a cycle through DPI and whose outputs are registered. That model holds the L1I, the ITLB, branch prediction, 68k decode, long flows and the millicode sequencer.

    Its move to RTL is being done piece by piece. dec68k.sv, the PLA decoder that turns the common 68k instructions into at most four uops each, runs in RTL in simulation. The millicode ROM, the long-flow ROM, 68k decode, the aligner, the L1I, the ITLB and the predictor are still C++.

    Note

    The core's source is not public yet.
