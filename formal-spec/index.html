    Formal spec¶

    A machine-readable formal specification of the 68k's user-mode integer instructions, for checking the core's translation of them. It is Robert S. Boyer and Yuan Yu's MC68020 specification in Nqthm (public domain), run directly in Python and lifted from there to SMT-LIB for z3.

    Background: how the 1992 semantics worked, why SMT, and reusing the semantics under a different modelling approach.

    Repository: github.com/dsheffie/m68k-formal-spec

    Original sources:

    • The Nqthm-1992 examples (the spec is examples/yu/mc20-1.events, its lemmas mc20-2.events)
    • R. S. Boyer and Y. Yu, the MC68020 specification, UT Austin TR-92-04
    • Y. Yu, PhD thesis, UT Austin TR-93-09

    How it fits the project¶

    The core executes 68k instructions as uisa micro-ops, and the common ones go through PLA templates (PLA flow coverage). This spec is what those flows are proved against: for one 68k instruction at a time, z3 proves that its flow computes exactly what the spec says, the same registers, condition codes, PC and memory for every input (PLA flow proofs). A sweep of every flow where A7 is both an operand and moved by the instruction found two bugs, UNLK A7 and JSR through A7 (worked examples). Proving every flow is still in progress.

    The spec is of the 68020's user-mode integer set, which the 68040 shares. It does not cover what millicode handles (bitfields, BCD, CAS/CAS2, supervisor instructions, the FPU), exceptions or the MMU.

    MC68020 semantics in SMT, lifted from Boyer & Yu's Nqthm spec¶

    Input: nqthm/mc20-1.events from the Nqthm-1992 examples (examples/yu/), Boyer and Yu's formal specification of about 80% of the MC68020 user-mode instructions (public domain; TR-92-04). 573 defns, ending in stepi.

    For how the 1992 model worked, why this project uses SMT instead, and how the same semantics carry over to a different modelling approach, see BACKGROUND.md.

    How it works¶

    lift/nqthm.py reads the event file and runs the definitions directly in Python. Nothing is translated by hand. It works in two modes:

    • Concrete: the definitions exactly as written, with Nqthm naturals and binary-tree memory with protection maps. This is the reference.
    • Symbolic: register, CCR and memory values are bit-vector terms. Control that depends on data (a condition code, a divide-by-zero halt) becomes if-then-else, never a fork. The machine status becomes a symbolic symbol.

    Only the functions whose recursion runs over data bits are replaced with native bit-vector versions: head, tail, logand, logor, logeor, setn, and the byte-level memory access. So are the signed multiply and divide (itimes, iquotient, iremainder): Yu builds them sign-magnitude, which z3 handles badly, and the lift uses one two's-complement bvmul / bvsdiv / bvsrem instead. lift.py check N SEED muldiv checks those three against the unmodified definitions. Every instruction's semantics, the effective-address calculation and the flag functions are Yu's text.

    lift/smt.py holds hash-consed SMT-LIB terms with constant folding, a Python evaluator, and a printer that emits shared sub-terms once. Nqthm's naturals and integers are kept exact: a value is a w-bit term read as unsigned or signed, and widths grow as needed. For example, add on two 32-bit values is 33 bits before head 32. There is no silent wraparound.

    Use¶

    • python3 lift/lift.py smt D081 prints SMT-LIB for one instruction (opword plus extension words, hex). The inputs are d0..d7, a0..a7 (32-bit), ccr (8-bit) and mem (Array BV32 BV8). The outputs are out_<reg>, out_ccr, out_pc, out_status and out_mem.
    • python3 lift/lift.py check N SEED takes N random instructions with random inputs. It checks that the lift, evaluated at those inputs, equals the unmodified spec run concretely: status, all 16 registers, pc, CCR and every memory byte.
    • python3 lift/z3check.py N SEED checks that z3 reads the printed SMT-LIB the same way the Python evaluator does.

    Modelling choices that differ from the original¶

    • Memory protection is not modelled. The original has unavailable, ROM and RAM regions; here all of memory is readable and writable data. Code comes from a concrete overlay of the instruction's own bytes. A store into the code overlay is refused.
    • Negative zero is folded into 0. Nqthm's (minus 0) object becomes plain 0; negp already excluded it.

    What the spec covers¶

    It covers the 68020 integer user-mode set: MOVE family, ADD/SUB/CMP families, logic, shifts and rotates, MUL/DIV, bit operations, Bcc/BSR/DBcc/Scc, JMP/JSR/RTS/RTD/RTR, LINK/UNLK, LEA/PEA, EXG/EXT/SWAP, TAS, CMPM and MOVEP. It covers every 68020 addressing mode, including full-format and memory-indirect.

    It halts, with a reason, on everything else: bitfields, BCD, CAS/CAS2, CHK/CHK2/CMP2, MOVES, TRAP/TRAPcc, all supervisor instructions, coprocessor and FPU, and illegal modes. It has no exceptions, interrupts, MMU or caches.

    Status¶

    About 6,000 random instructions lifted and checked against the spec run concretely, with no disagreements; z3 reads the printed SMT-LIB as the evaluator does. make check reruns a sample. Needs Python 3 and the z3 binary on PATH.

    Proving the 68k core's flows¶

    pla/ proves the 68k core's micro-op flows against this lift, one instruction at a time (pla/README.md). EXAMPLES.md walks through two bugs the proofs found (UNLK A7, and JSR through A7) and shows what a passing proof looks like, with and without the multiply abstracted.

    Boyer & Yu's MC68020 specification (Nqthm)¶

    Unmodified copies of two event files from the Nqthm-1992 distribution, nqthm-1992/examples/yu/ (https://www.cs.utexas.edu/users/boyer/ftp/nqthm/nqthm-1992/examples/yu/):

    • mc20-1.events: Robert S. Boyer and Yuan Yu's formal specification of about 80% of the MC68020 user-mode instructions, published as UT Austin TR-92-04.
    • mc20-2.events: their definitions and lemmas about that specification. Kept for reference; the lift does not use it.

    Both files are placed in the public domain by their author (see each file's header, "Copyright (C) 1994 by Yuan Yu ... placed in the public domain").

    Further reading: - R. S. Boyer and Y. Yu, Automated proofs of object code for a widely used microprocessor, JACM 43(1), 1996. - Y. Yu, PhD thesis, UT Austin, 1992 (TR-93-09).
