    The 68k PLA flows against the lifted MC68020 spec¶

    The 68k front end (m68k, gen_pla68k.py) expands most opwords into a PLA flow: a few uisa uops. This directory has z3 prove, one instruction at a time, that the flow does what Yu's MC68020 spec (../lift) does. The proof covers every value of d0-d7, a0-a7, the CCR and memory, for the given extension words.

    What is compared¶

    • The flow side (prove_pla.cc): the uisa flow table (build/uisa_flows.inc, from spec/flows.yaml). The PLA ROM is generated from this table, and gen_pla68k.py checks every PLA opword's template expansion against it. The flow runs symbolically with uisa's own op semantics, build/uisa_smt.inc (tools/gen_smt.py, from the sem strings in spec/uisa.yaml: the C-subset semantics the ISS also runs). The model (model/uisa_machine.cc) supplies three things: the flow selection (select_flow, second-level decode included), the immediates, and the full-format layout, all from the concrete extension words. The full-format address computation itself runs symbolically. The code is prove_pnr's symbolic executor, cut down to flows.
    • The spec side (liftsmt.py): ../lift/lift.py's lift, with every output defined, constants and the status symbol included.
    • The query: the low 32 bits of each register and of the pc, the CCR's X N Z V C, and memory. Memory is compared by one free address outside the code overlay. Both sides read the instruction's own bytes from the overlay first, as the lift does. The input CCR's bits 7:5 are 0.
    • Halts: a uisa guest op's trap (a zero divide) must happen exactly where the spec halts with trap-exception. Inputs where the spec halts for any other reason (divu-overflow, divs-overflow: the spec leaves the 68020's overflow result undefined) are excluded, and the result says so.

    Multiply and divide¶

    z3 cannot prove two different multiplier (or divider) circuits equal in useful time: the six MULU/MULS.W fast-path instructions ran out an hour each. The multiplier is not where a flow goes wrong, so the proofs abstract it:

    • The lift (../lift/nqthm.py, symbolic overrides): Yu's itimes, iquotient and iremainder build a sign-magnitude result (several magnitude products or quotients chosen by the operands' signs). They are replaced by one two's-complement bvmul / bvsdiv / bvsrem, as logand and setn are. lift.py check N SEED muldiv validates the overrides against the unmodified definitions run concretely (MULU/MULS/DIVU/DIVS.W only).
    • Both sides (prove_pla.cc, abs_op): a multiply of two k-bit sign- (or zero-) extended operands (k = 16, 32) becomes an uninterpreted mulk{s,u}, commutative by argument order; a 32-bit dividend by a 16- or 32-bit divisor becomes div32_k{s,u} / rem32_k{s,u}, with SMT-LIB's zero divisor result written out. Each operand's extension is first proved as a lemma, so the replacement is exact; multiplies and divides by a constant are left bit-level. z3 then proves everything around the multiplier: operand selection, extension, which half lands where, the flags, writeback.
    • A counterexample under the abstraction is reported only if the original terms agree with its model; otherwise it is a TIMEOUT.
    • A result that used the abstraction says abstracted: <functions>: that instruction's product or quotient was not checked bit-level. PROVE_NO_ABSTRACT=1 turns the pass off.

    The user state is SR = 0 (user, interrupt level 0), the pc is the lift's CODE (0x00F01000), and z3 has a 60 s timeout per query (PROVE_TIMEOUT_MS; run_pla.py passes 30 s).

    Results¶

    prove_pla LIFT.smt2 HEX... prints one of:

    • PROVED (or PROVED excluding spec halts: ...)
    • CEX <outputs>: a counterexample. -v prints the inputs and both sides' values; -p NAME=VALUE pins an input (a register, ccr, or m32@ADDR, the long at ADDR) to get a counterexample with chosen values.
    • NOTCMP <why>: not comparable. Either the spec halts on every input (an instruction outside its coverage), or the flow is a decode-time exception (an illegal encoding).
    • UNHANDLED <why>: an op this executor does not model (probes, cas, FP, CSRs, the return stack).
    • TIMEOUT <outputs>

    Sets of instructions:

    • extract.py OUT.json ELF...: the instructions in the executable sections of -mfast-path ELFs (a linear sweep with uisa's tools/m68kdec.py lengths, kept when the map calls them PLA).
    • gen_all.py OUT.json [N]: every PLA opword with N extension-word samples (edge values, then random), index words kept brief format.
    • gen_a7.py OUT.json [N]: every PLA opword where A7 can be both an operand and moved by the instruction (A7 in an EA, A7 as an index, LINK / UNLK / PEA / JSR / BSR / RTS).
    • run_pla.py IN.json OUT.jsonl [-j N]: proves a set in parallel, resumably.

    The generators find the uisa checkout and the front end's opword map through UISA_DIR and PLA_FMAP (paths.py; the defaults are the sibling checkouts ../../uisa and ../../m68k). The Makefile takes UISA and Z3.
