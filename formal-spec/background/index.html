    Background: the 1992 MC68020 semantics, and why lift it into SMT¶

    How the 1992 work modelled the 68020¶

    Robert S. Boyer and Yuan Yu specified the MC68020 at UT Austin between about 1989 and 1992. It was the core of Yu's PhD thesis (TR-93-09). They did it in Nqthm, the Boyer–Moore theorem prover. This is a different thing from the Boyer–Moore string-search algorithm, though it is by the same two people. Nqthm is an automated theorem prover for a first-order logic that is essentially pure Lisp: total recursive functions over natural numbers, integers, pairs and symbols, with proof by rewriting and induction.

    An interpreter semantics. The machine is defined by an interpreter, not by axioms. A state is a 5-tuple: status, register file, pc, CCR and memory. The single-step function stepi decodes the instruction at the pc and returns the next state. stepn(s, n) applies it n times, stopping early when the status is no longer 'running. Each instruction is an ordinary function: add-ins reads its operands through the effective-address calculation, computes the result, computes each flag with its own function (add-c, add-v, ...), and writes the result back. Anything outside the model stops the machine with a reason symbol, such as 'divu-overflow or 'i-will-do-it-later for the bitfields. Undefined behaviour therefore never becomes silently wrong.

    • Values: natural numbers, not bit-vectors. head(x, n) is x mod 2^n, add(n, x, y) is (x + y) mod 2^n, and sign extension is arithmetic on naturals. Bitwise AND is a recursion over the bits.
    • Memory: a pair of sparse binary trees indexed by address bits. One holds bytes. The other is a protection map marking regions unavailable, ROM or RAM; instructions have to come from ROM.
    • Size: the specification is 573 definitions, about 128 KB or 80 pages. It covers about 80% of the user-mode instructions and every 68020 addressing mode, including memory-indirect and full-format indexing.

    Why definitions rather than axioms. Every function was admitted under Nqthm's definitional principle, which proves it terminates. So the specification is guaranteed consistent, as consistent as elementary number theory, and it is executable. Running stepn inside Nqthm made a 68020 simulator, though it took about a million Sun-3 instructions to simulate one 68020 instruction. That executability was the main defence of the specification's accuracy. It was tested against real hardware (Ken Albin at Computational Logic built a test suite) as well as read critically.

    How they proved programs. A correctness theorem for a machine-code program has the form

    p-statep(s)  ⟹  p-req(s, stepn(s, p-t(s)))

    That is: if the initial state satisfies the precondition (user mode, an even pc, the program loaded at the pc, enough stack, and the arguments meet the function's requirements), then after p-t(s) instructions the state satisfies the requirement. Proofs are symbolic execution of stepn by Nqthm's rewriter, plus induction for loops.

    None of this was push-button. It rests on a library of about 1,500 lemmas (about 250 KB, 140 pages) that teach the rewriter how to simplify head, add, memory reads and writes after other writes, address-disjointness, and so on. The thesis calls that library the most time-consuming part of about three years of work. With it, they proved GCC output for binary search, Quicksort and 21 of the 22 Berkeley C string functions correct, along with programs from the Verdix Ada and AKCL Common Lisp compilers.

    Why something modern and SMT-based¶

    The question this project asks is narrower than Yu's, and it suits a decision procedure:

    • It is a bounded question. We want to prove that the core's translation of each 68k instruction is right: a PLA template or uop flow produces the same registers, flags, pc and memory as the instruction, for every operand value. That is equivalence of two fixed-width bit-vector functions of a single step. There are no loops and no unbounded data, so it needs no induction. An SMT solver (z3) decides it automatically. Nqthm would need a hand-built lemma library to get through each kind of instruction.
    • It finds bugs. When an equivalence fails, z3 returns concrete operand values that show the difference. A failed Nqthm proof leaves the user to work out whether a lemma is missing or the theorem is false.
    • The bit-level arithmetic is native. z3's bit-vector theory reasons about extract, carries and two's complement directly. The 1992 model had to build these from natural numbers and prove lemmas about them.
    • It fits the tools already in use. uisa's op semantics are already compiled to z3 terms (tools/gen_smt.py). Both sides of the equivalence then live in one solver.
    • The lemmas don't carry over. Nqthm is effectively retired; ACL2 is its successor. The 1,500 lemmas were written to steer Nqthm's rewriter, and even a port to ACL2 would have to redo most of them. The specification itself is the lasting part.

    SMT does not replace theorem proving everywhere. Properties over loops or unbounded memory, such as "this millicode routine terminates" or proofs of whole programs like Yu's, still need induction (ACL2 or Isabelle, for example). For per-instruction equivalence, the bounded half of the problem, SMT is the right tool.

    The semantics are reusable under a different modelling approach¶

    Because Boyer and Yu wrote an interpreter, the specification says what each instruction does without committing to how anyone reasons about it. The same definitions can be run in different ways, and this repository runs them in two:

    • Concretely, exactly as written: Nqthm naturals, binary-tree memory with protection maps. This is the reference.
    • Symbolically: registers, CCR and memory are bit-vector terms. Each if whose condition depends on data becomes an if-then-else term, and the result of one stepi is a set of SMT-LIB terms, one per register, the CCR, the pc, memory and the status.

    Only the modelling layer changes. Every instruction's semantics, the effective-address calculation and the flag functions are Yu's text, interpreted unchanged. What we replaced:

    Changed 1992 model Here
    Bit-level helpers (head, tail, logand, logor, logeor, setn) recursion over the bits of a natural native bit-vector extract, shifts and logic, giving the same values
    Byte-level memory access sparse binary trees with protection maps an SMT array of bytes over the instruction's own bytes; protection not modelled
    Numbers Nqthm naturals and integers exact bit-vector terms whose width grows as needed, so add on two 32-bit values is 33 bits until head truncates it; nothing wraps silently

    Because both modes run the same definitions, each checks the other. On about 6,000 random instructions, the symbolic result, evaluated at random inputs, matches the unmodified definitions run concretely, in status, every register, pc, CCR and every memory byte. z3 then confirms it reads the printed SMT-LIB the same way the Python evaluator does. The check found one bug in the lift: a PC-relative operand can read the instruction's own extension words, which the first memory model missed.

    The same specification could move again, to ACL2 for induction proofs or to Sail as a published ISA model. Each would be a new interpretation of the same definitions, not a new specification.
